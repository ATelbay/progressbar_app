# Progress Bar

Журнал силовых тренировок для тренера и подопечного. Flutter, iOS и Android из одной кодовой базы. Владелец делает его в первую очередь для себя.

С владельцем общайся по-русски, простыми словами: объясняй термины или обходись без них. Коммить только по его просьбе.

Shell-команды запускай через `rtk`: поддерживаемые напрямую, остальные — `rtk proxy <команда>`.

## С чего начать

1. Прочитай `docs/HANDOFF.md` — что сделано, на чём остановились, что осталось. Статус ведётся там; обновляй его, когда он меняется.
2. Прочитай `docs/REQUIREMENTS.md` — всё, что решено: что входит в MVP, что отложено, экраны, дизайн, сервер. Новое решение записывай туда; то, что владелец не подтверждал, — в раздел «К обсуждению».
3. Перед изменениями кода запусти `rtk proxy flutter analyze`, затем `rtk proxy flutter test` — должно быть чисто.

Не расширяй MVP без обсуждения с владельцем. Стабильные ID встроенного справочника и снапшоты истории сохранять.

## Что есть в приложении

- Вход по номеру телефона, первый профиль.
- Главная, конструктор программы, тренировка с панелью ввода, история с правкой, прогресс, профиль со справочником упражнений.
- Связи тренер–подопечный: приглашение и принятие по коду, деактивация и удаление тренера. Экран подопечного глазами тренера (`lib/features/people/trainee_screen.dart`) показывает текущие и завершённые тренировки, вкладки «Мои» / «Все» и назначения. Приглашение передаётся кодом, QR и ссылкой.
- Удаления аккаунта нет.

## Окружение и проверки на устройствах

**Firebase.** Проект `progressbar-app`, Firestore в `europe-west3`, тариф Blaze подключён. С 2026-10-07 включён Play Integrity API — он нужен для входа по настоящему SMS на Android. Приложения iOS и Android — `com.atelbay.progressbar`. Для запросов Google Cloud явно указывай `--account=arystantelbay@gmail.com` и `--project=progressbar-app`: проект по умолчанию в локальном gcloud другой. При аудите облака 2026-10-06 в проекте были только Firestore и служебные ресурсы Firebase; сумму расходов и бюджеты проверить не удалось (Cloud Billing Budget API выключен, его не включали).

**Эмуляторы вместо боевого проекта.** Экраны и офлайн проверяются на локальных эмуляторах Firebase: так не нужно менять настройки входа в облаке. Отладочная сборка с `--dart-define=USE_FIREBASE_EMULATORS=true` работает с ними (`lib/main.dart`), в обычной сборке переключатель выключен.

**Тестовый вход в боевом проекте.** В Firebase настроен отдельный вымышленный номер из диапазона US 555 со случайным шестизначным кодом. Параметры `TEST_PHONE` и `TEST_CODE` обязательны; передавай их через приватный JSON-файл вне репозитория и `--dart-define-from-file=<путь>` (раньше это был `/tmp/progressbar-auth-test.json`, он мог исчезнуть). Не использовать настоящий номер владельца с фиксированным кодом. Firebase применяет SMS-регион и к вымышленному номеру: при списке только KZ тест получает `operation-not-allowed`. Для проверки временно добавляли US и после каждого запуска возвращали KZ; итоговая конфигурация — только KZ. При повторном тесте обеспечь такое же восстановление, в том числе при ошибке.

**Настоящий телефон.** Для входа по SMS нужна выпускная сборка (`rtk proxy flutter build apk --release`, пока подписана отладочным ключом): в отладочной проверка телефона отключена. На Android вход по настоящему SMS сейчас не работает (HANDOFF, раздел «Телефон владельца и вход по SMS»); владелец временно добавил свой номер в тестовые сам. Журнал приложения на телефоне: `adb -s <серийный> logcat --pid=$(adb -s <серийный> shell pidof com.atelbay.progressbar)`.

**Память.** На Mac с 24 ГБ платформы собирать и проверять по очереди: выключать iOS-симулятор перед Android и наоборот, перед запуском смотреть давление на память. Android проверяли с `-memory 2048 -gpu host -no-snapshot -no-window`. В `android/gradle.properties` ограничены Java-куча (2 ГБ), метаданные (1 ГБ) и число задач (2). После проверок выключай симулятор и эмуляторы.

**Что проверено на устройствах.** Вход через боевой Firebase с вымышленным номером — на iOS (iPhone 17 Pro, iOS 26.4) и Android (Pixel 9), без отправки настоящего SMS. Все экраны, кроме связей, — на iPhone 17 Pro против эмуляторов (`tool/walkthrough.sh`), включая экран тренировки с крупным системным шрифтом. Офлайн и перезапуск — там же (`tool/offline_storage_test.sh`). На Android (эмулятор Pixel 9, 2026-10-07) против эмуляторов прошли основной проход, связи с назначениями, настоящая ссылка-приглашение, окно «Поделиться» и офлайн с перезапуском; подробности и найденное — в HANDOFF, раздел «Android».

## Экраны

- `lib/features/workout/workout_screen.dart` — экран, карточки упражнений, шторка завершения. `entry_panel.dart` — панель ввода: итогом и по подходам. Что подставить в поля и что считать текущим упражнением решает чистая логика в конце `lib/domain/workout_logic.dart` (`summaryDraft`, `setDraft`, `nextExercise`, `factSummary`…).
- `lib/features/format.dart` — числа и строки вида «3 × 12 × 15 кг», плашки «по плану / ниже плана». `lib/widgets/` — `GlassCard`, `Barbell` (гриф с блинами), `StepButton`, `PbPill`.
- `lib/features/exercises/exercise_picker_screen.dart` открывается маршрутом `Routes.exercisePicker` и возвращает выбранное упражнение через `context.pop(exercise)`.
- Репозитории получают базу из `firestoreProvider` (`lib/features/firestore_provider.dart`); в виджет-тестах он подменяется на `FakeFirebaseFirestore`. Справочник в виджет-тестах загружается один раз в `setUpAll` и подставляется в `exerciseCatalogProvider`: загрузка asset, закэшированная одним тестом, в следующем зависает.
- `lib/features/program/program_builder_screen.dart` — конструктор: название правится прямо в заголовке, дни — плашками (повторное касание открытого дня — переименовать или удалить), упражнение планируется одной строкой «подходы × повторения × вес» с заметкой. Изменения сохраняются сразу, но только когда у программы есть название. Чистая логика — `lib/domain/program_logic.dart`. Маршруты: `/program` — новая, `/program/<id>` — существующая. Есть «Начать тренировку» и «Назначить подопечному». Назначенный план открывается по /assigned/<coachId>/<programId>: только просмотр и старт от имени текущего пользователя.
- `lib/features/history/history_screen.dart` — история: самая новая тренировка раскрыта (план и факт по упражнениям), остальные — карточками, касание раскрывает. `workout_edit_screen.dart` (маршрут `/workout-edit/<id>`) правит завершённую тренировку: изменения копятся в черновике и уходят в хранилище только по «Сохранить изменения»; пометку «изменено после завершения» ставит логика тренировки. Правка открывает ту же панель ввода в шторке.
- `lib/features/progress/progress_screen.dart` — прогресс: выбор из упражнений, по которым есть результаты (`exercisesWithResults`), крупное последнее значение, изменение с первой точки, график (рисуется своим `CustomPainter`, без сторонней библиотеки) и список точек. Точки считает `progressFor`.
- Число рядом с названием в одной строке выводи через `NumberText(..., beside: true)`: длинное число тогда сжимается, а не выдавливает название.
- `lib/features/profile/profile_screen.dart` — профиль: имя и вес тела (касание по панели), язык, режим ввода, переход в справочник, выход. Язык хранится в профиле (`UserProfile.languageCode`, пусто — как в телефоне) и применяется в `lib/app.dart`; до входа язык всегда системный.
- Справочник — тот же `ExercisePickerScreen` с `manage: true` (маршрут `Routes.exerciseCatalog`): касание открывает `ExerciseEditSheet`. В нём же создаётся своё упражнение, в том числе прямо из выбора упражнения. Название правится только на текущем языке интерфейса; оборудование не редактируется.
- Шторки делай через `showPbSheet` и `PbSheet` / `ChoiceSheet` из `lib/widgets/sheet.dart` (в конструкторе программы пока своя копия `_Sheet`).
- Тяжесть вводится тремя ответами (`Effort` в `workout_logic.dart`), хранится числом 7 / 8,5 / 10.
- `SummaryEntry` (`lib/features/workout/summary_entry.dart`) — общий последовательный ввод результата итогом и плана: подходы → повторения → вес (у времени — секунды без веса). Нижняя кнопка переводит к следующему полю, сохраняет только на последнем; любое поле можно выбрать касанием, первая цифра заменяет подсказку. Черновик и проверка чисел — `lib/domain/summary_input.dart`. Известный вес в плане сначала показывается с шестью кнопками шага; касание поля открывает клавиатуру. `NumberKeypad` — общие цифровые клавиши для этого ввода и прежнего `WeightKeypad` режима по подходам. День тренировки выбирается кнопкой `WorkoutDayButton` (системный календарь).
- Тема берётся из профиля (`UserProfile.theme`, «как в телефоне» по умолчанию) и применяется в `lib/app.dart`; до входа — как в телефоне.
- Экран тренировки закрывается сам, когда активная тренировка исчезает (завершена или отменена). Кнопки «назад» на нём нет, как в макете: выход — системным жестом.
- В обоих режимах упражнения всегда идут в порядке `workout.exercises`: выбор раскрывает панель ввода на месте карточки. После смены текущего упражнения экран прокручивается к панели (`_followPanel`). `ExerciseLabels` показывает отдельно «Вне плана», «Записано», сравнение с планом и «не отправлено». «Записано» означает наличие факта, включая частично записанное упражнение по подходам, и не зависит от отправки на сервер. `isOutsidePlan` в домене отличает добавленное упражнение по копии плана, а не по идентификатору упражнения в справочнике; дополнительные подходы в плановом упражнении этой пометки не дают.

## Связи

- `links/{coachId}_{traineeId}` — связь двух людей со статусом `active`, `readOnly` или `removed` и именами обеих сторон на момент создания (профили закрыты, другую сторону видно только через эти имена). `invitations/{код}` — одноразовое приглашение на 7 дней; код из шести знаков без похожих символов.
- Связь появляется только принятием приглашения: принимающий одной пачкой пишет связь и удаляет приглашение, правила проверяют роли, срок и то, что приглашение использовано. Дальше связь меняет только подопечный и только вниз: в «просмотр» или в «удалён». Вернуть активность — новым приглашением. Удалить документ связи не может никто.
- Тренер читает все тренировки подопечного, пока связь `active` или `readOnly`; также читает свои назначения этому подопечному; при активной связи может назначать свои программы. Тренировка может назвать в `supervisorCoachId` только активного тренера, и после создания это поле не меняется.
- **Один активный тренер — без гарантии сервера.** Когда приглашает подопечный, связь создаёт тренер, и старую активную связь он тронуть не может. Поэтому активным считается самый новый (`activeCoachOf`, `activeCoachProvider`), а старые в «просмотр» переводит телефон самого подопечного (`lib/features/shell.dart`, `linksToDemote`). До его выхода в сеть прежний тренер формально остаётся активным. Серверного кода (Cloud Functions) в проекте нет.
- Всё это требует сети, поэтому `LinkRepository` ждёт ответа сервера и может бросить ошибку — в отличие от хранилищ тренировок.
- Экраны: `lib/features/people/people_screen.dart`, `invite_screens.dart`; логика — `lib/domain/link_logic.dart`.
- Ссылка приглашения — `progressbar://app/join/<код>` (`inviteLink`); она же в QR (`lib/widgets/qr_code.dart`). Входящую ссылку разбирает `redirect` в `lib/router.dart`: код уходит в `pendingInviteCodeProvider`, а экран принятия поверх главной открывает `lib/features/shell.dart` — отдельного экрана у ссылки нет, иначе с него некуда вернуться. Маршруты пересоздаются при смене сессии, и ссылку, с которой приложение запущено, читает только первый (`overridePlatformDefaultLocation`), иначе приглашение откроется дважды. «Поделиться» в тестах подменяется через `shareTextProvider`.

## Хранение данных

Всё лежит под `users/{uid}`. Пишет только сам пользователь; читать его тренировки может ещё его тренер (см. «Связи»):

- `programs/{id}` — программа целиком, дни и упражнения внутри документа. `ProgramRepository`.
- `workouts/{id}` — тренировка целиком: копия плана и факт по подходам. `WorkoutRepository`.
- `exercises/{id}` — свои упражнения (ID `custom/…`) и правки встроенных (тот же ID, что во встроенном справочнике). В имени документа `/` заменён на `~`. `PersonalExerciseRepository`; итоговый справочник даёт `mergeCatalog` и `userCatalogProvider`.
- `state/activeWorkout` — указатель на единственную активную тренировку.

Преобразование моделей в документы — `lib/data/firestore_codec.dart`. Провайдеры: `lib/features/workout/workout_providers.dart`, `lib/features/program/program_providers.dart`, `lib/features/exercises/personal_exercises_provider.dart`.

Правила, которые легко сломать:

- **Одна активная тренировка.** Указатель и тренировка меняются только вместе, одной пачкой записей (`WriteBatch`). Правила на сервере отклоняют активную тренировку, на которую указатель не указывает, поэтому писать тренировку мимо `WorkoutRepository` нельзя. Завершённую тренировку можно исправить, но нельзя снова открыть.
- **Записи не ждут сервера.** Без сети запись в Firestore «висит» до появления связи, поэтому репозитории возвращают управление сразу (`sendWrite`), а отказ сервера приходит в `onRejected`. Не добавляй `await` на запись в Firestore — экран зависнет в зале без сети.
- **Записи уходят по одной.** `sendWrite` (`lib/data/firestore_writes.dart`) выпускает следующую запись, только когда предыдущая появилась в локальном хранилище: на Android плагин отдаёт каждую запись своему потоку, и две отправленные разом могут примениться в обратном порядке. Свою запись он узнаёт по полю `writeId`, которое кладётся в документы тренировок, программ и своих упражнений. Любую новую запись этих документов отправляй через `sendWrite`, а не напрямую. Ждать локального хранилища можно (миллисекунды, сеть не нужна, предел две секунды), сервера — нет.
- **Подтверждение отправки.** `WorkoutSyncRepository` отдельно слушает метаданные документа с `includeMetadataChanges: true`. `isFromCache` означает отсутствие подтверждения сервера, а не достоверное отсутствие интернета; экран пишет «Ждём связи с сервером». `hasPendingWrites` даёт пометки «не отправлено» у записанных результатов; они восстанавливаются из кэша после перезапуска и исчезают после подтверждения. Тренировка — один документ, поэтому статус общий для всех её записанных упражнений. Не сохраняй эти метаданные в модель истории.
- **Отказ сохранить.** Провайдеры тренировок, программ и личных упражнений передают `rejectedWriteHandler` в `onRejected`. `StorageWriteNotice` над маршрутизатором показывает сообщение даже после закрытия исходного экрана; оно привязано к пользователю и очищается при выходе. Это уведомление об отказе, а не резервная копия отклонённой записи. Обработчики живут в процессе: отказ от записи, оставшейся с прошлого запуска, отдельно ещё не перехватывается. Ошибки профиля этим обработчиком не покрыты.
- **Проверка перед стартом** читает указатель из памяти репозитория, затем из локального кэша, и только если о нём ничего не известно — с сервера. Если нет ни кэша, ни сети — `WorkoutStoreUnavailable`. Чтобы этого не случалось, главный экран должен слушать `activeWorkoutProvider` сразу после входа.
- День, за который засчитана тренировка, — `performedOn` (строка «2026-10-07», пусто — день завершения). Сортируй и показывай тренировки по `performedAt(workout)`, а не по `completedAt`.
- Отмена тренировки удаляет её документ; отменить можно только тренировку без записей. Завершённую удаляет `deleteCompleted` с экрана правки. Свои упражнения не удаляются (на них ссылаются программы), правку встроенного можно сбросить.

Что чем проверено — таблица в `docs/HANDOFF.md`. В тестах на подставной базе `fake_cloud_firestore` после записи нужен `await pumpEventQueue()`: она не проверяет ни правила доступа, ни офлайн.

## Как устроен код

- `lib/domain/` — модели и чистая логика без Flutter и Firebase. Всё новое поведение сначала пишется здесь и покрывается тестами.
- `lib/data/` — доступ к Firebase за интерфейсами (`AuthRepository`, `ProfileRepository`, `ProgramRepository`, `WorkoutRepository`, `PersonalExerciseRepository`, `LinkRepository`). Вход и профиль в тестах подменяются на `test/support/fakes.dart`, хранение — настоящие репозитории поверх `FakeFirebaseFirestore`.
- `lib/features/<раздел>/` — экраны. Состояние — Riverpod, маршруты — go_router (`lib/router.dart`).
- `lib/widgets/` — общие виджеты: `GlowBackground` (фон со светом), `GlassPanel` и `GlassCard` (стекло), `Barbell`, `StepButton`, `PbPill`, шторки из `sheet.dart`.
- `lib/design/tokens.g.dart` — генерируется, руками не править.
- `lib/l10n/` — строки. Каждая строка есть во всех трёх файлах. Казахский переводил ИИ, его нужно вычитать носителю.

Правила, которые легко нарушить:

- План и факт хранятся раздельно и никогда не смешиваются.
- План копируется в тренировку при старте; изменение программы не переписывает историю.
- Упрощённый ввод «подходы × повторения × вес» — только способ ввода, хранится всё по подходам.
- Вес тела участвует только в упражнениях с флагом `usesBodyWeight`.
- Цвета, отступы и стили текста берутся из `PbColors`, `PbSpace`, `PbRadius`, `PbText` — не пиши значения руками.
- Основные действия — в нижней половине экрана, области касания не меньше 48.

## Грабли

- `flutterfire configure` требует Ruby-библиотеку `xcodeproj`, которой нет в системном Ruby. Её ставили во временную папку (`gem install xcodeproj --install-dir <папка>`) и запускали с `GEM_HOME`/`GEM_PATH` на неё. Перезапускать команду нужно только при добавлении новой платформы.
- Первая сборка под Android идёт около 15 минут.
- `flutter doctor` ругается на отсутствие Android cmdline-tools и лицензий; сборке это не мешает.
- В отладочных сборках включён `appVerificationDisabledForTesting`. Для такого входа номер должен быть добавлен в тестовые в Firebase и его регион разрешён на время проверки. В релизе настройка выключена.
- Вход по SMS на настоящем iPhone потребует ключ push-уведомлений Apple, а значит платный аккаунт разработчика. У владельца его пока нет.
- Сквозной тест не содержит номера и кода по умолчанию и завершится до обращения к Firebase, если параметры не переданы.
- macOS заблокировала `impellerc` из установленного Homebrew Flutter SDK. После снятия карантина с этого конкретного бинарника сборка iOS прошла.
- Эмуляторам Firebase нужна Java 21+, а `JAVA_HOME` указывает на 17. Подходит Java из Android Studio: `export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"; export PATH="$JAVA_HOME/bin:$PATH"`.
- `flutter test integration_test/…` после прогона удаляет приложение с устройства вместе с локальной базой Firestore, поэтому перезапуск так не проверить; вход при этом остаётся в связке ключей iOS. Для перезапуска — `tool/offline_storage_test.sh`.
- Аккаунтов разработчика Apple и Google Play ещё нет; доставка через сторы отложена.
- Проходы используют постоянные тестовые номера. Если между прогонами не перезапускать эмуляторы Firebase, пользователь уже существует и `walkthrough_test` не увидит анкету. Очистка: `curl -X DELETE http://localhost:9099/emulator/v1/projects/progressbar-app/accounts`.
- `adb` не в PATH: `export PATH="$HOME/Library/Android/sdk/platform-tools:$PATH"`. Android блокирует нешифрованный HTTP к эмуляторам Firebase; для отладочной сборки это разрешено в `android/app/src/debug/AndroidManifest.xml`.

## Назначения программ (часть 2, 2026-10-06)

- Назначения: `users/{traineeId}/assignments/{coachId}_{programId}`, поля `coachId`, `traineeId`, `programId`, серверный `assignedAt`. Программа остаётся у автора. Составной ID отделяет одноимённые ID программ разных авторов.
- `AssignmentRepository` ждёт серверное подтверждение (15 секунд до ошибки подтверждения); повторная попытка пишет тот же документ. Программы и тренировки по-прежнему пишутся через `sendWrite` без ожидания сети.
- Только активный тренер назначает свою существующую программу. Подопечный читает назначенный документ и упражнения автора при связи active/readOnly. Писать чужой план/упражнения нельзя. Список назначений для тренера обязательно фильтруется по coachId.
- Справочник автора объединяется со встроенным только для назначенного плана; личные правки подопечного его не подменяют. После удаления связи назначения скрываются при получении нового статуса, включая открытый план.
- `WorkoutRepository.watchAll` читает текущие и завершённые тренировки без закрытого указателя состояния. «Мои» фильтруется по supervisorCoachId. Имя супервизора сохраняется в supervisorCoachName при старте и не меняется при правке. В старой истории без имени показано «имя не сохранено».
- Живой тест двух аккаунтов: `rtk proxy python3 tool/links_walkthrough.py <simulator-id> build/links-walkthrough`; Firebase Auth и Firestore должны быть запущены локально. Проверяет приглашение, назначение, живое обновление плана, офлайн, деактивацию и удаление.
- Перед deploy: `rtk proxy python3 tool/verify_firestore_rules.py` сравнивает сервер с HEAD. Если последний deploy ещё не закоммичен, передай `--expected-file firestore.rules` или сохранённую копию последнего deploy. После deploy всегда сравни с текущим файлом.

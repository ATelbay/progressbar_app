# Progress Bar — требования

Живой документ. Пункт попадает в «Решено», «MVP» или «Отложено» только после того, как мы его обсудили.
Всё, что ещё не подтверждено, лежит в «К обсуждению».

## Решено

- **Название:** Progress Bar — и под иконкой, и в сторах. Уточнение добавляется только там, где нужен уникальный идентификатор.
- **Идентификаторы:** проект `progressbar_app`, bundle ID / applicationId `com.atelbay.progressbar`.
- **Платформы:** iOS и Android из одной кодовой базы на Flutter.
- **Роли:** тренер составляет план, спортсмен записывает прогресс. Типа аккаунта нет: роль при регистрации не выбирается, «тренер» и «подопечный» — это стороны связи между двумя аккаунтами.
- **Вход:** по номеру телефона, код по SMS через Firebase. Почта опциональна.
- **Сервер:** входит в MVP.
- **Источник справочника упражнений:** `yuhonas/free-exercise-db` (общественное достояние). Отбираем популярные, названия переводим на русский и казахский. Встроенная подборка реализована: 127 упражнений в `assets/exercises/catalog.json`; происхождение и правила правки — `assets/exercises/README.md`. Казахские названия требуют вычитки носителем.
- **Основа:** продуктовая идея CoachTrack (`~/AndroidStudioProjects/CoachTrack-experiment`, ТЗ — `projects/coachtrack-06/TASK.md`).

## Функциональные требования

### MVP

- **Основа из CoachTrack** (переносится без изменений, отдельно не обсуждалось):
  - план и факт хранятся раздельно;
  - снапшот плана при старте тренировки — изменение программы не переписывает историю;
  - конструктор программы: программа → дни → упражнения → плановые подходы;
  - запись факта: вес, повторения, RPE по желанию; подход сверх плана; отмена тренировки;
  - одна активная тренировка одновременно;
  - история тренировок с разницей между планом и фактом.
- **Одиночный режим:** любой пользователь может сам составить себе программу и заниматься без тренера.
- **Создание связи:** один общий вход для обеих сторон. Приглашающий выбирает, в какой роли он зовёт (как тренер или как подопечный); в приглашении видно, кто и в какой роли приглашает. Связь появляется после принятия.
- **Способы приглашения:** код, ссылка и QR. Поиска по почте нет.
- **Тренеры подопечного:** активный тренер один — только он назначает программы. Принятие приглашения от нового тренера делает его активным; приложение спрашивает подтверждение.
- **Деактивация и удаление тренера:** подопечный может деактивировать тренера — тогда у того остаётся доступ на чтение; или удалить — тогда тренер теряет доступ полностью.
- **Что видит тренер:** по умолчанию — тренировки по своим программам; в отдельной вкладке — все тренировки подопечного.

- **Журнал тренировок:** все тренировки принадлежат спортсмену; у каждой тренировки записано, под чьим патронажем она прошла (активный тренер на момент старта). По этой отметке тренер видит «свои» тренировки.
- **Профиль:** вес тела пользователя — нужен для упражнений с собственным весом.
- **Чем измеряется упражнение:** переключатель «повторения» или «время».
- **Единицы:** только килограммы.
- **Языки интерфейса:** русский, английский, казахский.

- **Справочник упражнений:** готовый список популярных упражнений, который пользователь может редактировать — добавлять свои и менять существующие.
- **Тренировка без программы:** можно записать тренировку без плана. Если есть активный тренер, он её супервизор; если нет — она просто попадает в журнал.
- **Правка завершённой тренировки:** спортсмен может исправить свою тренировку после завершения; тренер видит пометку «изменено после завершения».
- **Два режима ввода результата:** это только способ ввода, данные хранятся одинаково — по подходам. Упрощённый (по умолчанию): количество подходов, повторения и вес одной строкой; количество подходов запоминается для следующего ввода. Полный: редактор по каждому подходу. Кнопки переключают режимы в обе стороны, выбор сохраняется в настройках пользователя.
- **Удаление аккаунта:** доступно в самом приложении (требование Apple).
- **Подстановка прошлого результата:** поля ввода заранее заполнены результатом прошлой тренировки по этому упражнению. Если прошлого результата нет — значением из плана. Прошлый результат важнее плана, хотя в макете показан план (подтверждено 2026-10-06).
- **Прогресс:** одна точка на завершённую тренировку. Упражнение с весом — максимальный вес; на время — максимальное время; с собственным весом — максимум повторений, а если был дополнительный вес, то повторения с самым тяжёлым из них.
- **Вес тела в упражнениях:** учитывается только там, где упражнение отмечено «с собственным весом» (подтягивания, брусья). Там поле ввода — дополнительный вес, а в истории видна полная нагрузка: вес тела плюс дополнительный. В остальных упражнениях вес тела не участвует. Вес тела запоминается в тренировке на момент её старта.
- **Сравнение с планом:** вес больше, а повторений меньше — «ниже плана»; записано меньше подходов, чем в плане, — упражнение «ниже плана».
- **Программа тренера:** общая. Тренер её правит, изменения попадают в будущие тренировки подопечного; подопечный менять её не может.
- **Шаги значений:** вес кратен 0,25 кг; оценка тяжести хранится числом от 1 до 10 с шагом 0,5.
- **Ввод тяжести:** три ответа вместо шкалы (решено 2026-10-06): «Могу ещё» — 7 и меньше, хранится 7; «Остались силы» — 8–9, хранится 8,5; «Больше не могу» — 10. По желанию, только в режиме ввода по подходам.
- **Отмена тренировки** (решено 2026-10-06): удаляет тренировку без следа, отдельного «перенести» нет — расписания в приложении нет, тренировку можно начать заново. Если не записано ни одного упражнения, тренировку можно только отменить, в историю пустая не попадает.
- **Заметки:** заметка тренера к упражнению в программе; комментарий спортсмена к тренировке.

### Отложено

- Переезд на другой телефон / работа с нескольких устройств одного пользователя.
- Таймер отдыха — до решения, которое не заставляет носить телефон с собой.
- Фунты.
- Замена упражнения во время тренировки.
- Чтение данных из Apple Health, Samsung Health и подобных.
- Личные рекорды и тоннаж.
- Вскоре после MVP: калькулятор блинов, суперсеты.
- Вскоре после MVP: картинка или видео техники в карточке упражнения. Нужны база упражнений и надёжный источник свободных материалов. Кандидат — `yuhonas/free-exercise-db`: общественное достояние (Unlicense), 876 упражнений на английском с картинками и описанием техники, видео нет.
- Сильно позже: приложение для часов (Apple Watch, Wear OS) и вместе с ним таймер отдыха и автосчёт повторений.
- В дальний ящик: геймификация, замеры тела и фото прогресса.
- Чат тренера и подопечного.
- Push-уведомления («назначена программа», «тренировка завершена»).

## Нефункциональные требования

### MVP

- **Обновление в реальном времени:** пока приложение открыто, изменения с другой стороны (новая программа, записанный подход, завершённая тренировка) появляются сами, без ручного обновления.
- **Офлайн:** без сети работает всё, что спортсмен делает в зале: начать тренировку, записать результаты, завершить. Данные уходят на сервер сами, когда появляется связь. Без сети не работают вход и приглашения.
- **Версии систем:** iOS 15 и новее, Android 7.0 (API 24) и новее — минимум, который поддерживает Flutter 3.47. По данным StatCounter за апрель 2026 это 96,6 % устройств Android.
- **Устройства:** телефоны, только портретная ориентация.
- **Темы:** светлая и тёмная, по системной настройке.
- **Тесты:** автотесты на бизнес-логику.
- **Стоимость сервера:** цель — бесплатный уровень Firebase плюс оплата SMS.

### Отложено

- Планшеты и альбомная ориентация.
- E2E-тесты на ключевые сценарии.
- Доставка сборок через TestFlight и внутреннее тестирование Google Play — когда появятся аккаунты разработчика (Apple — $99 в год, Google Play — $25 разово).

## Экраны

1. **Вход:** номер телефона → код из SMS → имя и вес тела при первом входе.
2. **Главная:** активная тренировка (если есть), мои программы, кнопка «тренировка без программы».
3. **Конструктор программы:** дни → упражнения → плановые подходы.
4. **Тренировка:** список упражнений дня, окно ввода результата в двух режимах, завершение.
5. **История:** список тренировок, внутри — план и факт.
6. **Прогресс:** график по упражнению.
7. **Люди:** мои тренеры и мои подопечные, приглашение (код, ссылка, QR), деактивация и удаление.
8. **Подопечный глазами тренера:** его тренировки (вкладки «мои» и «все»), назначенные ему программы.
9. **Профиль и настройки:** вес тела, язык, режим ввода, справочник упражнений, удаление аккаунта.

Нижняя панель: Главная, История, Прогресс, Люди, Профиль. Экраны 3, 4 и 8 открываются поверх.

## Дизайн

- **Темы:** тёмная «Закат» и светлая «Рассвет», выбираются по настройке системы. Стекло — основной материал, под ним три пятна тёплого света; акцент янтарный.
- **Шрифты:** Golos Text для текста, Fira Sans Extra Condensed для цифр. Файлы лежат в `assets/fonts/`, лицензия OFL.
- **Источник значений:** `design/system/project/tokens.json`. Из него командой `dart run tool/gen_tokens.dart` собирается `lib/design/tokens.g.dart`; руками этот файл не правится.
- **Дизайн-система:** https://claude.ai/artifact/6pwDsPNipiAAuBUTsjePsU, исходники в `design/system/project/`.
- **Экраны:** https://claude.ai/artifact/7W4jACbBWunMDcjJUQ4Znc, исходники в `design/screens/project/`. Страница «Экраны» — девять основных, страница «Состояния» — вход по шагам, пустые экраны, без сети, подтверждения, приглашение, варианты ввода.
- **Проверка:** Impeccable установлен в `.claude/skills/impeccable`; отчёт в `.impeccable/critique/`.

Решения, принятые в макетах:

- Вес вводится кнопками «минус» и «плюс» с шагом 2,5 кг или с цифровой панели по касанию числа.
- Удаление аккаунта подтверждается вводом слова «удалить».
- Упражнения, не записанные к моменту завершения, тренер видит как пропущенные.
- При удалении тренера тренировки остаются у подопечного.
- На слабых Android и при настройке «уменьшить прозрачность» стекло заменяется непрозрачной поверхностью.

## Сервер

- **Firebase-проект:** `progressbar-app` («Progress Bar»), владелец arystantelbay@gmail.com.
- **Приложения:** Android и iOS с идентификатором `com.atelbay.progressbar`. Для Android добавлены отпечатки отладочного ключа (SHA-1 и SHA-256).
- **База:** Cloud Firestore, регион `europe-west3` (Франкфурт); регион изменить нельзя.
- **Правила доступа:** `firestore.rules`, развёрнуты 2026-10-06. Пользователю открыты только его профиль, программы, тренировки, упражнения и указатель активной тренировки; всё остальное закрыто. Доступ тренера появится вместе со связями.
- **Хранение:** всё под `users/{uid}`: `programs`, `workouts`, `exercises` и `state/activeWorkout`. Программа и тренировка — по одному документу. Правило «одна активная тренировка» обеспечивают и приложение, и правила сервера. Без сети записи копятся на устройстве и уходят сами, в том числе после перезапуска приложения.
- **Подключение к коду:** `lib/firebase_options.dart`, `android/app/google-services.json`, `ios/Runner/GoogleService-Info.plist` созданы командой `flutterfire configure`.

Сделано в консоли: включён вход по номеру телефона, разрешена отправка SMS в Казахстан, подключён Blaze. Привязка биллинга подтверждена через Cloud Billing API 2026-10-05.

Проверка 2026-10-06: настроен отдельный вымышленный тестовый номер. Сквозные тесты входа прошли на iOS и Android: вход, профиль в Firestore (чтение с сервера) и выход. SMS не отправлялись; доставка настоящего SMS остаётся непроверенной. Для вымышленного US-номера регион US временно разрешали и возвращали KZ после каждого теста; итоговый список разрешённых регионов — только KZ.

Осталось:

- перед выпуском проверить вход с настоящим SMS на физических устройствах;
- перед выпуском проверить настройки тестового входа; настоящий номер пользователя не должен допускать вход по фиксированному тестовому коду.

## К обсуждению

Приняты при реализации хранения (2026-10-06), владельцем не подтверждены:

- **Удаление своего упражнения** не предусмотрено: его можно только изменить. Правку встроенного упражнения можно сбросить к исходному.
- **Старт без сети сразу после первого входа:** если приложение ещё ни разу не получило с сервера сведения об активной тренировке и сети нет, старт не разрешается. В обычной работе это не встречается — вход и так требует сети.

Приняты при реализации экрана тренировки (2026-10-06), владельцем не подтверждены:

- **Количество подходов по умолчанию:** столько, сколько в плане; без плана — столько, сколько вводили в прошлый раз, а в самый первый раз три.
- **Шаги кнопок:** повторения по 1, время по 5 секунд, вес по 2,5 кг; точный вес — с цифровой панели.
- **Язык интерфейса** выбирается в профиле: «как в телефоне», русский, английский или казахский. Выбор хранится в профиле на сервере; до входа язык всегда как в телефоне.
- **Правка упражнения:** меняются название (на текущем языке интерфейса), группа мышц из шести общих, измерение и признак собственного веса. Оборудование не редактируется.
- **Плашка сравнения с планом** пока показывает только слова «по плану», «ниже плана», «выше плана», без разницы в килограммах.

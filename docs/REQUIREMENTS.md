# Progress Bar — требования

Живой документ. Пункт попадает в «Решено», «MVP» или «Отложено» только после того, как мы его обсудили.
Всё, что ещё не подтверждено, лежит в «К обсуждению».

## Решено

- **Название:** Progress Bar — и под иконкой, и в сторах. Уточнение добавляется только там, где нужен уникальный идентификатор.
- **Идентификаторы:** проект `progressbar_app`, bundle ID / applicationId `com.atelbay.progressbar`.
- **Платформы:** iOS и Android из одной кодовой базы на Flutter.
- **Роли:** тренер составляет план, спортсмен записывает прогресс. Типа аккаунта нет: роль при регистрации не выбирается, «тренер» и «подопечный» — это стороны связи между двумя аккаунтами.
- **Вход:** по номеру телефона, код по SMS через Firebase. Почта опциональна.
- **Сервер:** входит в MVP.
- **Источник справочника упражнений:** `yuhonas/free-exercise-db` (общественное достояние). Отбираем популярные, названия переводим на русский и казахский. Встроенная подборка реализована: 127 упражнений в `assets/exercises/catalog.json`; происхождение и правила правки — `assets/exercises/README.md`. Казахские названия требуют вычитки носителем.
- **Основа:** продуктовая идея CoachTrack (`~/AndroidStudioProjects/CoachTrack-experiment`, ТЗ — `projects/coachtrack-06/TASK.md`).

## Функциональные требования

### MVP

- **Основа из CoachTrack** (переносится без изменений, отдельно не обсуждалось):
  - план и факт хранятся раздельно;
  - снапшот плана при старте тренировки — изменение программы не переписывает историю;
  - конструктор программы: программа → дни → упражнения → плановые подходы;
  - запись факта: вес, повторения, RPE по желанию; подход сверх плана; отмена тренировки;
  - одна активная тренировка одновременно;
  - история тренировок с разницей между планом и фактом.
- **Одиночный режим:** любой пользователь может сам составить себе программу и заниматься без тренера.
- **Создание связи:** один общий вход для обеих сторон. Приглашающий выбирает, в какой роли он зовёт (как тренер или как подопечный); в приглашении видно, кто и в какой роли приглашает. Связь появляется после принятия.
- **Способы приглашения:** код, ссылка и QR. Поиска по почте нет.
- **Тренеры подопечного:** активный тренер один — только он назначает программы. Принятие приглашения от нового тренера делает его активным; приложение спрашивает подтверждение.
- **Деактивация и удаление тренера:** подопечный может деактивировать тренера — тогда у того остаётся доступ на чтение; или удалить — тогда тренер теряет доступ полностью.
- **Что видит тренер:** по умолчанию — тренировки по своим программам; в отдельной вкладке — все тренировки подопечного.

- **Журнал тренировок:** все тренировки принадлежат спортсмену; у каждой тренировки записано, под чьим патронажем она прошла (активный тренер на момент старта). По этой отметке тренер видит «свои» тренировки.
- **Профиль:** вес тела пользователя — нужен для упражнений с собственным весом.
- **Чем измеряется упражнение:** переключатель «повторения» или «время».
- **Единицы:** только килограммы.
- **Языки интерфейса:** русский, английский, казахский.

- **Справочник упражнений:** готовый список популярных упражнений, который пользователь может редактировать — добавлять свои и менять существующие.
- **Тренировка без программы:** можно записать тренировку без плана. Если есть активный тренер, он её супервизор; если нет — она просто попадает в журнал.
- **Правка завершённой тренировки:** спортсмен может исправить свою тренировку после завершения; тренер видит пометку «изменено после завершения».
- **Два режима ввода результата:** это только способ ввода, данные хранятся одинаково — по подходам. Упрощённый (по умолчанию): количество подходов, повторения и вес одной строкой; количество подходов запоминается для следующего ввода. Полный: редактор по каждому подходу. Кнопки переключают режимы в обе стороны, выбор сохраняется в настройках пользователя.
- **Удаление аккаунта:** доступно в самом приложении (требование Apple).
- **Подстановка прошлого результата:** поля ввода заранее заполнены результатом прошлой тренировки по этому упражнению. Если прошлого результата нет — значением из плана. Прошлый результат важнее плана, хотя в макете показан план (подтверждено 2026-10-06).
- **Прогресс** (пересмотрен по просьбе владельца 2026-11-15): одна точка на завершённую тренировку. Вкладка открывается списком упражнений с результатами — сначала недавние, с поиском (регистр и «е/ё» не важны). В строке: последнее значение, лучший подход под названием, изменение от первой точки и маленький график. Касание открывает экран упражнения внутри вкладки: график, значение, изменение и все точки. Упражнение с весом по умолчанию показывает **расчётный максимум на один повтор** по формуле Эпли (вес × (1 + повторения / 30); при одном повторе — сам вес), округлённый до 0,5 кг и помеченный «≈», — так больше повторений при том же весе тоже видно как рост. Лучший подход тренировки для оценки — с наибольшей оценкой, при равенстве — более тяжёлый; ступени дроп-сета для оценки не берутся. Переключатель «Максимум / Вес / Повторения»: «Вес» — самый тяжёлый вес (при равенстве больше повторений, ступени дроп-сета учитываются), «Повторения» — повторения этого самого тяжёлого подхода. Выбранный вариант помнится до закрытия приложения. Условность оценки выше примерно 12 повторений принята владельцем 2026-11-16: сохраняются знак ≈ и единая формула. В пустом прогрессе есть «К программам» с тем же переходом, что в пустой истории. Без веса (все подходы 0 кг) остаются только повторения. На время — максимальное время; с собственным весом — максимум повторений, а если был дополнительный вес, то повторения с самым тяжёлым из них, расчётного максимума для них нет. Точки берутся только из записей с тем же способом измерения и признаком собственного веса, что у последней записи.
- **Вес тела в упражнениях:** учитывается только там, где упражнение отмечено «с собственным весом» (подтягивания, брусья). Там поле ввода — дополнительный вес, а в истории видна полная нагрузка: вес тела плюс дополнительный. В остальных упражнениях вес тела не участвует. Вес тела запоминается в тренировке на момент её старта.
- **Сравнение с планом** (решение владельца 2026-11-16): для подходов на повторения с нагрузкой сравниваются округлённые до 0,5 кг оценки максимума по Эпли: вес × (1 + повторения / 30), при одном повторе — сам вес. Больше — «выше плана», меньше — «ниже плана», равно после округления — «по плану», даже если исходные вес и повторения различаются. Для `usesBodyWeight` прибавляется вес тела, сохранённый при старте тренировки. Если вес тела в тренировке не сохранён, полная нагрузка неизвестна и оценка не считается: как на время, снижение веса или повторений — «ниже плана», рост без снижения — «выше плана», пояснение «≈» не показывается (изменено 2026-11-17 по ревью; прежде вес тела считался нулём — см. «К обсуждению»). Когда обе нагрузки нулевые, сравниваются повторения. В паре с нагрузкой нулевые повторения или нулевая нагрузка дают оценку 0. На время сохраняется сравнение секунд и заданного веса: снижение любого означает «ниже плана». Каждая плановая ступень дропа сравнивается отдельно. Недостающий плановый подход/ступень делает частично записанное упражнение «ниже плана»; полностью пустое — пропущенным после завершения. Дополнительные подходы не компенсируют пропущенные. 3 × 80 считается выше 12 × 60; это принято владельцем. Общая формула используется и в прогрессе, доступные метрики графика остаются прежними.
- **Пояснение сравнения** (2026-11-16): в истории, у тренера и в редакторе рядом с «выше / ниже плана» показывается «≈ X кг против ≈ Y кг» только если в решающем подходе вес и повторения изменились в противоположных направлениях. Для «ниже» берётся первый плановый подход/ступень ниже плана, для «выше» — первый выше. У пропусков, времени, равенства и в живой панели пояснения нет. Поведение плашки «по плану» сохраняется.
- **После деактивации и удаления тренера** (подтверждено 2026-10-06): после деактивации назначенные программы остаются доступны; после удаления тренера доступ закрывается. Выполненные тренировки остаются у подопечного.
- **Тема** (решено 2026-10-07): в профиле выбирается «как в телефоне», тёмная или светлая; до входа — как в телефоне.
- **Лист планирования упражнения в конструкторе** (решено 2026-10-07, макеты `BuilderPlan` и `BuilderPlanKeypad`): вес меняется шестью кнопками под числом, в два ряда на всю ширину листа — сверху +0,5, +1, +5, под ними −0,5, −1, −5; шаги выбрал владелец. Касание по самому числу открывает клавиатуру веса. Подставляется самый тяжёлый вес из последней записи этого упражнения у автора программы, сверху строка «В прошлый раз: …». Если записей нет — клавиатура открыта сразу; порядок ввода уточнён ниже. Стаж и пол не спрашиваем, формул «от веса тела» нет.
- **Сохранение с клавиатуры планирования** (подтверждено 2026-10-08): одно «Готово» сохраняет упражнение и закрывает весь лист. Шаги ±0,5 / ±1 / ±5 кг для изменения известного веса оставляем (повторно подтверждены владельцем).
- **Ввод в листе планирования с клавиатуры** (решено 2026-10-08, реализовано 2026-10-09): подходы, повторения и вес вводятся с клавиатуры по очереди; кнопка называется «Продолжить», на весе — «Готово». Клавиатура заменяет кнопки шага веса: они показываются, только когда есть значение для подстановки (прошлый результат или уже сохранённый план).
- **Последовательный ввод результата «Итогом»** (уточнено владельцем 2026-10-08, реализация разрешена и выполнена 2026-10-09): используется кастомная цифровая клавиатура, как при вводе веса. Сначала активно поле подходов; нижняя кнопка переводит фокус к повторениям, затем к весу. Переходы между полями не записывают промежуточный результат; итог записывается после ввода веса. Отдельный новый редактор для этого не нужен.
- **Упражнение сверх плана в тренировке** (решено 2026-10-08, реализовано 2026-10-09): помечается «Вне плана» до и после записи результата. Возможность добавить его в план — после согласования показанных вариантов дизайна.
- **Порядок упражнений в тренировке** (согласовано по отзыву владельца, реализовано 2026-10-09): панель ввода раскрывается на месте выбранной карточки. В обоих режимах порядок карточек остаётся как в тренировке; добавленные упражнения идут после плановых.
- **Перестановка упражнений** (просьба владельца 2026-11-15, выбран вариант «удержать и тащить»): немедленное перетаскивание за ручку «≡» справа или долгое касание тела свёрнутой карточки прямо в списке тренировки; одна ручка на суперсет, открытая панель без ручки; суперсет переносится целиком, экран сам прокручивается у края. Открытая панель ввода не перетаскивается и остаётся открытой со своим черновиком; следующее упражнение после записи текущего берётся уже по новому порядку. Экранный диктор получает действия «выше / ниже / в начало / в конец». В истории порядок фактический; исходный порядок до первой перестановки сохраняется в тренировке (`originalOrder`), показывается в истории спортсмена, на экране подопечного у тренера (текущие и завершённые, «Мои»/«Все», active/readOnly) и только для чтения в редакторе. Пометка «Порядок изменён» раскрывает нумерованные группы сохранённого плана; если до перестановки добавляли упражнения вне плана или плана нет — также «До перестановки». Поздние добавления не дописываются в снимок. При возврате исходного порядка пометка скрывается, снимок сохраняется. Отметок у отдельных фактических упражнений и номеров фактического порядка нет (уточнение владельца 2026-11-16).
- **Пропуск упражнения** (просьба владельца «не сделал» 2026-11-15): у открытого упражнения без результатов кнопка «Пропустить» — экран переходит к следующему, карточка помечается «Пропущено», блин на грифе становится низким и бледным. «Отменить пропуск» снимает пометку без записи; запись результата снимает её сама. Суперсет пропускается целиком. План пропущенного упражнения не меняется; в истории и у тренера оно «пропущено», как и оставленное пустым. В шторке завершения — отдельные строки «Записано N из M», «Пропущено K» и «Без результата K», у последних двух — названия упражнений; нулевые строки скрыты. При пустых упражнениях показано пояснение, что тренер увидит их как пропущенные. Слово «Пропустить» выбрано вместо «Не сделал»: оно не зависит от рода и совпадает с «пропущено» в истории.
- **Способ выполнения** (согласовано 2026-10-13, реализовано 2026-10-14): в плане и при записи доступны обычное упражнение, суперсет и дроп-сет. Способ задаётся для упражнения или группы внутри дня; способы можно сочетать в одной тренировке. Выбор выполнения отделён от записи «Итогом / По подходам». В плане стоит переключатель из трёх сегментов; при крупном шрифте — раскрывающийся список. Без программы способ выбирается до ввода результатов; прямо при создании суперсета можно добавить упражнения из справочника.
- **Суперсеты** (согласовано 2026-10-13, реализовано 2026-10-14): группа из N упражнений, количество кругов и своя нагрузка каждого. «Итогом» — количество кругов, затем повторения/время и вес каждого упражнения; «Продолжить» ведёт по полям и упражнениям, «Записать суперсет» сохраняет всю группу. «По подходам» — упражнения первого круга, затем следующего, с сохранением каждого подтверждённого подхода. Группа не завершает общую тренировку. Уже заполненное можно выбрать для исправления.
- **Дроп-сеты** (согласовано 2026-10-13, реализовано 2026-10-14): один подход содержит начальную нагрузку и ступени снижения, например 60 кг × 10 → 45 кг × 8 → 30 кг × 6. В плане задаются число таких подходов и, при желании, ступени. «Продолжить» ведёт по повторениям/времени и весу, затем по запланированным ступеням; «Ещё снижение» добавляет ступень по ходу, «Записать дроп-сет» заканчивает подход. Можно закончить раньше плана — незаписанные плановые ступени остаются без факта. «Итогом» повторяет одну введённую последовательность для выбранного числа дроп-сетов; «По подходам» допускает разные веса, повторения и число снижений в каждом, сохраняет подтверждённые ступени и позволяет продолжить после прерывания.
- **Сохранение групп и история** (2026-10-14): переходы между числовыми полями оставляют черновик; полный ввод сохраняет готовый подход суперсета или ступень дроп-сета, итоговый — всю заполненную группу. Если фактические результаты различаются, правка доступна по подходам, а «Итогом» недоступен, чтобы не заменить их одним шаблоном. Запись меньшего числа кругов/дроп-сетов завершает ввод, сохраняя незаполненную часть плана. История показывает состав суперсета, нагрузки по подходам и цепочки ступеней дроп-сета; правка завершённой тренировки поддерживает те же режимы. Исходный способ выполнения и группа плана копируются при старте и сохраняются отдельно от способа выполнения, выбранного в тренировке.
- **Кнопка «Удалить программу»** (решено 2026-10-07) видна, как только у программы есть название.
- **Экран тренировки** (решено 2026-10-07) после каждой записи сам прокручивается к панели ввода.
- **Отмена и удаление тренировки** (решено 2026-10-07): «Отменить тренировку» в шторке завершения есть только у тренировки без единой записи. Тренировку с записями завершают; завершённую можно удалить на экране её правки в истории, с подтверждением. Удаление необратимо.
- **День тренировки** (решено 2026-10-07): в шторке завершения и на экране правки стоит день, по умолчанию сегодня; его можно сменить на более ранний через системный календарь, будущий выбрать нельзя. Только день, без времени. История и прогресс упорядочены по этому дню; настоящее время завершения хранится как было. Смена дня у завершённой тренировки ставит пометку «изменено после завершения».
- **Снятие назначения** (решено 2026-10-06): отдельного действия «снять назначение» в MVP нет. Достаточно того, что при смене тренера прежний переходит в «просмотр», а удаление тренера закрывает доступ к его программам.
- **Удаление назначенной программы тренером** (решено 2026-10-06): не запрещается и без предупреждения. Подопечный видит на её месте «Программа недоступна»; выполненные тренировки хранят свою копию плана и не меняются.
- **Программа тренера:** общая. Тренер её правит, изменения попадают в будущие тренировки подопечного; подопечный менять её не может.
- **Шаги значений:** вес кратен 0,25 кг; оценка тяжести хранится числом от 1 до 10 с шагом 0,5.
- **Ввод тяжести:** три ответа вместо шкалы (решено 2026-10-06): «Могу ещё» — 7 и меньше, хранится 7; «Остались силы» — 8–9, хранится 8,5; «Больше не могу» — 10. По желанию, только в режиме ввода по подходам.
- **Отмена тренировки** (решено 2026-10-06): удаляет тренировку без следа, отдельного «перенести» нет — расписания в приложении нет, тренировку можно начать заново. Если не записано ни одного упражнения, тренировку можно только отменить, в историю пустая не попадает.
- **Заметки:** заметка тренера к упражнению в программе; комментарий спортсмена к тренировке.

## Нефункциональные требования

### MVP

- **Обновление в реальном времени:** пока приложение открыто, изменения с другой стороны (новая программа, записанный подход, завершённая тренировка) появляются сами, без ручного обновления.
- **Офлайн:** без сети работает всё, что спортсмен делает в зале: начать тренировку, записать результаты, завершить. Данные уходят на сервер сами, когда появляется связь. Без сети не работают вход и приглашения.
- **Версии систем:** iOS 15 и новее, Android 7.0 (API 24) и новее — минимум, который поддерживает Flutter 3.47. По данным StatCounter за апрель 2026 это 96,6 % устройств Android.
- **Устройства:** телефоны, только портретная ориентация.
- **Темы:** светлая и тёмная, по системной настройке.
- **Тесты:** автотесты на бизнес-логику.
- **Стоимость сервера:** цель — бесплатный уровень Firebase плюс оплата SMS.

### Отложено

- Планшеты и альбомная ориентация.
- E2E-тесты на ключевые сценарии.
- Доставка сборок через TestFlight и внутреннее тестирование Google Play — когда появятся аккаунты разработчика (Apple — $99 в год, Google Play — $25 разово).

## Сервер

- **Firebase-проект:** `progressbar-app` («Progress Bar»), владелец arystantelbay@gmail.com.
- **Приложения:** Android и iOS с идентификатором `com.atelbay.progressbar`. Для Android добавлены отпечатки отладочного ключа (SHA-1 и SHA-256).
- **База:** Cloud Firestore, регион `europe-west3` (Франкфурт); регион изменить нельзя.
- **Правила доступа:** `firestore.rules`, развёрнуты 2026-10-06. Пользователь пишет только свои профиль, программы, тренировки, упражнения и указатель активной тренировки. Тренер читает тренировки подопечного, пока связь активна или только для просмотра; удалённый тренер не видит ничего. Активный тренер пишет назначения своих программ. Подопечный читает назначенную программу и упражнения автора, но не меняет их. После удаления связи этот доступ закрывается.
- **Связи и приглашения:** коллекции `links` и `invitations`. Связь появляется только принятием приглашения, меняет её потом только подопечный.
- **Хранение:** всё под `users/{uid}`: `programs`, `workouts`, `exercises` и `state/activeWorkout`. Программа и тренировка — по одному документу. Правило «одна активная тренировка» обеспечивают и приложение, и правила сервера. Без сети записи копятся на устройстве и уходят сами, в том числе после перезапуска приложения.
- **Подключение к коду:** `lib/firebase_options.dart`, `android/app/google-services.json`, `ios/Runner/GoogleService-Info.plist` созданы командой `flutterfire configure`.

Сделано в консоли: включён вход по номеру телефона, разрешена отправка SMS в Казахстан, подключён Blaze. Привязка биллинга подтверждена через Cloud Billing API 2026-10-05.

Проверка 2026-10-06: настроен отдельный вымышленный тестовый номер. Сквозные тесты входа прошли на iOS и Android: вход, профиль в Firestore (чтение с сервера) и выход. SMS не отправлялись; доставка настоящего SMS остаётся непроверенной. Для вымышленного US-номера регион US временно разрешали и возвращали KZ после каждого теста; итоговый список разрешённых регионов — только KZ.

Осталось:

- перед выпуском проверить вход с настоящим SMS на физических устройствах;
- перед выпуском проверить настройки тестового входа; настоящий номер пользователя не должен допускать вход по фиксированному тестовому коду.

## К обсуждению

Приняты при исправлениях по ревью (2026-11-17), владельцем не подтверждены:

- **Сравнение без веса тела.** В ревью предлагалось в таком случае сравнивать только повторения. Выбрано осторожное правило, как у упражнений на время: сравнение только повторений не заметило бы добавленного веса (10 × +10 кг вместо 10 без веса было бы «по плану»).
- **Суперсет итогом** открывается, только если у его упражнений с результатами записано одинаковое число кругов. Иначе правка идёт по подходам с пояснением «Результаты различаются»: один общий счётчик кругов дописал бы одному упражнению круг, которого не было.
- **Упражнение, добавленное в шторке «Способ выполнения»,** остаётся в тренировке, только если вошло в суперсет. Закрытие шторки или снятая отметка ничего не добавляют.

Приняты при пропуске, перестановке и новом прогрессе (2026-11-15), владельцем не подтверждены:

- **Пропуск и перестановка без сети** не дают пометки «не отправлено» на карточке (она только у записанных результатов); общая плашка «Ждём связи с сервером» при этом видна.

Приняты при реализации хранения (2026-10-06), владельцем не подтверждены:

- **Удаление своего упражнения** не предусмотрено: его можно только изменить. Правку встроенного упражнения можно сбросить к исходному.
- **Старт без сети сразу после первого входа:** если приложение ещё ни разу не получило с сервера сведения об активной тренировке и сети нет, старт не разрешается. В обычной работе это не встречается — вход и так требует сети.

Приняты при реализации экрана тренировки (2026-10-06), владельцем не подтверждены:

- **Количество подходов по умолчанию:** столько, сколько в плане; без плана — столько, сколько вводили в прошлый раз, а в самый первый раз три.
- **Шаги кнопок:** повторения по 1, время по 5 секунд, вес по 2,5 кг; точный вес — с цифровой панели.
- **Язык интерфейса** выбирается в профиле: «как в телефоне», русский, английский или казахский. Выбор хранится в профиле на сервере; до входа язык всегда как в телефоне.
- **Правка упражнения:** меняются название (на текущем языке интерфейса), группа мышц из шести общих, измерение и признак собственного веса. Оборудование не редактируется.
- **Плашка сравнения с планом** пока показывает только слова «по плану», «ниже плана», «выше плана», без разницы в килограммах.

Приняты при реализации связей (2026-10-06), владельцем не подтверждены:

- **Приглашение** — код из шести знаков, действует один раз и 7 дней. Срока в требованиях не было; он добавлен, чтобы забытый код не давал доступ к тренировкам бессрочно.
- **Возврат тренера в активные** после деактивации возможен только новым приглашением: кнопки «сделать снова активным» нет.
- **Смена активного тренера, когда приглашает подопечный:** новый тренер становится активным сразу, а прежний переходит в «просмотр», когда телефон подопечного выйдет в сеть. До этого прежний формально остаётся активным. Мгновенно это можно сделать только кодом на сервере, которого в проекте нет.
- **Имена** тренера и подопечного в связи — те, что были в момент принятия приглашения; после смены имени в профиле у другой стороны остаётся старое.
- **Ссылка приглашения** имеет вид `progressbar://app/join/<код>` — со своей схемой, а не https. В мессенджерах она обычно не нажимается, поэтому при «Поделиться» вместе с ней уходит код. QR содержит ту же ссылку и читается системной камерой; сканера внутри приложения нет. Нажимаемые https-ссылки потребуют аккаунта разработчика Apple и своего сайта.

Вход по настоящему SMS на Android (2026-10-07), решение не принято:

- **Что случилось.** Выпускная сборка на телефоне владельца (Samsung, оператор ALTEL / activ) не получила SMS: проверка Play Integrity отвечает «приложение не распознано Play Store», запасная проверка в браузере проходит, после неё Firebase отказывает с «Error code: 39». Платёжный аккаунт, регион KZ и отпечатки ключа в порядке.
- **Причина не установлена.** Предположение: Firebase не шлёт SMS на этот номер после одной только запасной проверки — либо для региона нужна полноценная проверка приложения через Google Play, либо дело в операторе.
- **Варианты:** проверить номер другого оператора (покажет, оператор это или проверка приложения); завести аккаунт разработчика Google Play (25 долларов разово) и загрузить сборку во внутреннее тестирование, чтобы Play Integrity проходил; перевести проект на Identity Platform, чтобы увидеть серверный журнал отказов; написать в поддержку Firebase.
- **Временное решение владельца:** он сам добавил свой настоящий номер в тестовые номера Firebase с фиксированным кодом и так вошёл. Пока номер в тестовых, любой, кто знает номер и этот код, войдёт в его аккаунт без SMS. Перед выпуском номер из тестовых нужно убрать и проверить, что вход по фиксированному коду больше не работает.

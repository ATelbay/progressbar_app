## Телефон владельца и вход по SMS

- 2026-10-07 выпускная сборка Android (`rtk proxy flutter build apk --release`, подписана отладочным ключом) установлена на его Samsung Galaxy S25 (`adb -s RFCY2058QBE …`) и работает с боевым Firebase. Отладочная сборка для входа по SMS не годится: в ней отключена проверка телефона. Сборка содержит всё по последний коммит.
- **Вход по настоящему SMS не прошёл.** Цепочка в журнале телефона: `requestIntegrityToken` → `18002 Invalid PlayIntegrity token; app not Recognized by Play Store` → запасная проверка `RecaptchaActivity` в браузере → `17499 Error code:39`, в приложении «не получилось войти». Проверено чтением настроек: вход по телефону включён, регион KZ разрешён, отпечатки SHA-1 и SHA-256 совпадают с ключом сборки, платёжный аккаунт привязан. Включение Play Integrity API не помогло: приложение не распространяется через Google Play, поэтому Play Integrity его не узнаёт.
- **Причина кода 39 не установлена.** Проект на обычном Firebase Auth (`subtype: FIREBASE_AUTH`), серверный журнал запросов входа доступен только после перехода на Identity Platform. Предположение: Firebase не шлёт SMS на этот номер после одной только запасной проверки — из-за региона или оператора (ALTEL / activ). Варианты для владельца записаны в «К обсуждению» в требованиях: номер другого оператора, аккаунт разработчика Google Play с внутренним тестированием, Identity Platform, поддержка Firebase.
- **Сейчас владелец входит через тестовый номер:** он сам добавил свой настоящий номер в тестовые номера Firebase с фиксированным кодом. Приложение на его телефоне пишет в боевую базу — это первые настоящие данные в ней. Перед выпуском номер из тестовых убрать. Агенту самому настоящие номера в тестовые не добавлять.
- На эмуляторе Pixel 9 у владельца стоит отладочная сборка с `USE_FIREBASE_EMULATORS=true`; она работает, только пока запущены локальные эмуляторы Firebase.

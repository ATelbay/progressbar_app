## Нет сети и ошибки сохранения (2026-10-08)

- `WorkoutSyncRepository` слушает метаданные нативного Firestore; `WorkoutSyncState` в домене определяет пометки записанных результатов. Данные тренировки и схема Firestore не менялись. Плашка «Ждём связи с сервером» появляется без подтверждения от сервера, «не отправлено» — пока есть записи в очереди. Достоверное отсутствие интернета приложение не определяет. Поскольку тренировка хранится одним документом, статус общий для её записанных упражнений.
- Пометки переживают остановку и запуск приложения, снимаются при подтверждении отправки. После добавления метаданных офлайн с перезапуском повторно проверен на обеих платформах: обе фазы прошли, накопленный результат подтверждён чтением с сервера.
- `rejectedWriteHandler` подключён к репозиториям тренировок, программ и личных упражнений. `StorageWriteNotice` над маршрутизатором показывает отказ даже после ухода с исходного экрана, сообщение закрывается по «ОК», при выходе из аккаунта очищается. Поздняя ошибка старого пользователя новому не показывается.
- На iPhone 17 Pro и Pixel_9_coach прошёл `integration_test/storage_status_test.dart`: отключение связи, запись, обе темы, крупный шрифт, возврат связи и снятие пометок, настоящие отказы локального сервера для всех трёх репозиториев. Отказ тренировки проверяется с откатом к прежнему серверному результату и переходом на главную. На снимках исправлена почти невидимая «ОК» в светлой теме (`inversePrimary` в `theme.dart`). Итоговые 9 снимков каждой платформы просмотрены: `build/verification-20261008/{ios,android}-storage/`.
- **Ограничения:** это показ отказа, без резервной копии и автоматического повторения отклонённых изменений. Обработчик отказа живёт в текущем процессе: если запись восстановлена с прошлого запуска, её последующий отказ отдельно ещё не перехватывается. Отказы профиля этим обработчиком не покрыты. Казахские новые строки добавлены, носителем не вычитаны.

Отладочная сборка для входа по SMS не годится: в ней отключена проверка телефона. Сборка содержит всё по последний коммит.
- **Вход по настоящему SMS не прошёл.** Цепочка в журнале телефона: `requestIntegrityToken` → `18002 Invalid PlayIntegrity token; app not Recognized by Play Store` → запасная проверка `RecaptchaActivity` в браузере → `17499 Error code:39`, в приложении «не получилось войти». Проверено чтением настроек: вход по телефону включён, регион KZ разрешён, отпечатки SHA-1 и SHA-256 совпадают с ключом сборки, платёжный аккаунт привязан. Включение Play Integrity API не помогло: приложение не распространяется через Google Play, поэтому Play Integrity его не узнаёт.
- **Причина кода 39 не установлена.** Проект на обычном Firebase Auth (`subtype: FIREBASE_AUTH`), серверный журнал запросов входа доступен только после перехода на Identity Platform. Предположение: Firebase не шлёт SMS на этот номер после одной только запасной проверки — из-за региона или оператора (ALTEL / activ). Варианты для владельца записаны в «К обсуждению» в требованиях: номер другого оператора, аккаунт разработчика Google Play с внутренним тестированием, Identity Platform, поддержка Firebase.
- **Сейчас владелец входит через тестовый номер:** он сам добавил свой настоящий номер в тестовые номера Firebase с фиксированным кодом. Приложение на его телефоне пишет в боевую базу — это первые настоящие данные в ней. Перед выпуском номер из тестовых убрать. Агенту самому настоящие номера в тестовые не добавлять.
- На эмуляторе Pixel 9 у владельца стоит отладочная сборка с `USE_FIREBASE_EMULATORS=true`; она работает, только пока запущены локальные эмуляторы Firebase.

## Что ещё осталось в MVP

- **Удаление аккаунта** (требование Apple). Не начато, кнопки в профиле нет. Необратимо: профиль, программы, тренировки, упражнения, указатель активной тренировки, связи, назначения, приглашения и сам вход. Владелец ждёт, что ему сначала покажут список удаляемого и скажут, что будет, если удаление оборвётся на середине. Правила сейчас никому не разрешают удалять связи — их придётся дополнить.
- **Доработка ошибок сохранения:** отказ записи, восстановленной с прошлого запуска, пока отдельно не перехватывается; профиль не подключён к общему показу отказов. Плашка на тренировке, пометки и отказы текущего запуска для тренировок, программ и упражнений уже реализованы и проверены на обеих платформах.
- **Комментарий спортсмена к тренировке**: в модели и хранилище есть, вводить негде.
- **Разница с планом в цифрах** («−2 кг от плана»): сейчас только слова.
- **Конструктор:** разные подходы в плане одного упражнения, перестановка дней и упражнений.
- **Вход по настоящему SMS** на Android (см. выше) и на iPhone (нужен платный аккаунт разработчика Apple).
- **Казахский перевод** сделан ИИ и не вычитан носителем; с каждым этапом строк больше.
- **Полная проверка русского и казахского на всех экранах:** просмотрен профиль на ru/kk с крупным шрифтом и тренировка с состояниями сети на ru; основной проход и связи в основном идут на английском.

## Вопросы к владельцу

Записаны в `docs/REQUIREMENTS.md`, раздел «К обсуждению»; он их ещё не подтверждал. Коротко:

- своё упражнение нельзя удалить, только изменить;
- старт без сети запрещён, если приложение ни разу не связалось с сервером после входа;
- число подходов по умолчанию и шаги кнопок на панели ввода;
- язык хранится в профиле; название упражнения правится только на текущем языке; оборудование не редактируется;
- приглашение действует 7 дней и один раз;
- тренер, которого деактивировали, вернуть в активные можно только новым приглашением;
- при приглашении «я подопечный» старый активный тренер теряет активность не мгновенно, а когда телефон подопечного выйдет в сеть;
- ссылка приглашения со своей схемой не нажимается в мессенджерах;
- что делать со входом по SMS на Android.

И одно наблюдение с живого прогона, по которому владелец не ответил: если записать один подход из трёх и переключиться на «Только итог», в поле «Подходы» стоит 1, а не 3 из плана.

Уже решено владельцем (в требованиях это в принятых): подставлять прошлый результат, а не план; тяжесть — три ответа (хранится 7 / 8,5 / 10); отдельного «снять назначение» нет; тренер удаляет назначенную программу без запрета; всё из раздела «Правки по заметкам владельца».
